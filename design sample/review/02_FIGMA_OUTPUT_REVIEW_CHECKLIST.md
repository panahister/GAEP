# Figma Output Review Checklist

## File and shell consistency

- [ ] Figma variables exist for color, type, spacing, radius, elevation, and timeline semantics.
- [ ] The shell is a reused component, not redrawn per screen.
- [ ] Sidebar width, top bar, breadcrumbs, content margins, and page headers are consistent.
- [ ] Future modules are disabled and non-clickable.
- [ ] Service & Schedule active state is identical across screens.

## Visual fidelity

- [ ] Primary desktop frames are complete at 1440 px and credible at 1280 px.
- [ ] Typography hierarchy and compact density match the design system.
- [ ] Borders and restrained elevation define structure without card clutter.
- [ ] Provisional maritime identity is calm and non-derivative.
- [ ] No excessive gradients, glass effects, playful art, or oversized radii appear.

## Component reuse and behavior

- [ ] Tables, filters, forms, time pairs, chips, banners, dialogs, drawers, and toasts are components with variants.
- [ ] Baseline/actual/projected legend and tokens are consistent.
- [ ] Position/Sequence and omitted/locked row variants are reusable.
- [ ] Scenario rail, change summary, milestone editor, and schedule timeline are componentized.
- [ ] Interactive states include hover, focus, selected, disabled, loading, error, and read-only.

## Content and data

- [ ] All visible content is professional English and LTR.
- [ ] No lorem ipsum or meaningless chart data appears.
- [ ] Fictional service, voyage, vessel, ports, dates, and variances are internally consistent.
- [ ] Voyage Number and CVN are both shown where required.
- [ ] Every operational time includes local and UTC labels.
- [ ] Units and identifiers are consistent.

## Accessibility

- [ ] Text/control contrast meets the proposed AA target.
- [ ] Focus styles are visible on every custom interaction.
- [ ] Status meaning is not color-only.
- [ ] Timeline/map alternatives exist.
- [ ] Fields have visible labels and associated error text.
- [ ] Keyboard order and overlay focus-return are annotated.

## Responsive design

- [ ] Shell variants exist for desktop, laptop, tablet, and narrow.
- [ ] Wide tables have reduced-column/card alternatives.
- [ ] Simulation and Line Study tablet patterns use drawers/stacked editors.
- [ ] Narrow screens honestly restrict unsafe complex editing while preserving viewing.

## Prototype connections

- [ ] Primary deviation-recovery path has no dead end.
- [ ] Planning path returns correctly between Service Workspace and Line Study.
- [ ] Apply confirmation links to success and refreshed Monitor.
- [ ] Back, Close, Cancel, and breadcrumbs work everywhere.
- [ ] Future module placeholders do not navigate.
- [ ] Reduced-motion or instant-transition fallback is available.
