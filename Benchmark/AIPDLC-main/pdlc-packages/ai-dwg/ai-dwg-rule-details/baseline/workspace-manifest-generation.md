# Workspace Manifest Generation — The Discovery Contract

## Purpose

Defines how AI-DWG generates `.governance/workspace-manifest.yaml` — the **discovery contract** that every downstream consumer (AI-GCE, AI-TGE, AI-FLO, and any future package) reads to locate workspace contents **by semantic role**, never by hardcoded path. This is the decoupling layer: when DWG changes the layout, it updates the manifest, and consumers adapt automatically — zero downstream breakage.

**Output:** `{workspace-root}/.governance/workspace-manifest.yaml`

**Condition:** Always (every generation and re-baseline regenerates it).

**Grounding:** Implements layout design Part 3E + drift design §17.2. DWG generation side.

---

## MANDATORY: Stage Sub-Role — Automation Engineer

Automation Engineer mindset (machine-readable contracts, deterministic lookups). ADDS a dimension — does NOT replace the primary role.

### Behavioral Shifts
- The manifest is an API, not documentation — machine-parseable, stable keys, no prose
- Every path/file entry must resolve to a real location in THIS generation
- Semantic keys are the contract — `files.definitionOfDone`, not a hardcoded string consumers duplicate

### Anti-Patterns
- Do NOT include entries for clusters/files that weren't generated
- Do NOT let consumers hardcode paths — the manifest exists so they don't
- Do NOT hand-maintain — regenerate from the actual file set every time

---

## The Decoupling Principle

```
DWG writes → .governance/workspace-manifest.yaml
                    ↓ (read by role, not path)
   GCE  ─ manifest.paths.rules → scans rules/ (not ".kiro/steering/")
   TGE  ─ manifest.paths.backlog → finds stories
   FLO  ─ manifest.files.driftRegister → reads drift state
```

No consumer hardcodes a path. DWG changes layout → updates manifest → consumers adapt. This is why GCE's 132 hardcoded `.kiro/steering/` refs collapse to one: "read the manifest."

## workspace-manifest.yaml Schema

```yaml
# .governance/workspace-manifest.yaml
# Generated by AI-DWG — DO NOT EDIT MANUALLY
# All downstream consumers (GCE, TGE, FLO) read this to discover workspace structure
---
dwgVersion: v1.1
baselineVersion: v{N}
projectId: PRJ-{ABBREV}-{YYYY}-{NNN}
storyStyle: {ears | invest | job-story | freestyle | hybrid}
platformTargets: [kiro, claude-code]
generatedOn: {ISO-timestamp}
# buildProfile: PARKED — not populated (build-method-agnostic)

# ─── Folder Locations (look up by role, never hardcode) ───
paths:
  rules: rules/
  backlog: backlog/                # omit if POLC absent
  architecture: architecture/      # omit if ADLC absent
  ux: ux/                          # omit if UXD absent
  info: info/
  src: src/                        # omit if ADLC absent (no scaffold)
  governance: .governance/
  managementFramework: management_framework/
  contextMap: WORKSPACE_CONTEXT_MAP.md

# ─── Key Files (look up by semantic role) ───
files:
  workspaceRules: rules/workspace-rules.md
  relevanceMap: rules/relevance-map.md            # omit if not generated
  definitionOfDone: backlog/DEFINITION_OF_DONE.md
  definitionOfReady: backlog/DEFINITION_OF_READY.md
  scopeAndRisks: backlog/scope-and-risks.md
  traceabilityMatrix: backlog/traceability-matrix.md
  valueMetrics: backlog/value-metrics.md
  userStories: backlog/user-stories.md            # omit if not Tier 2
  poCharter: backlog/po-charter.md
  prioritizationRegister: backlog/prioritization-register.md
  vision: info/vision.md
  technicalEnvironment: architecture/technical-environment.md
  constraintRegister: architecture/constraint-register.md
  architectureDecisionRecords: architecture/architecture-decision-records.md
  uiSpec: ux/ui-implementation-spec.md
  driftRegister: .governance/drift-register.md
  baselineManifest: .governance/baseline-manifest.yaml

# ─── Platform Adapters (which wiring exists) ───
adapters:
  kiro: .kiro/steering/            # present only if kiro in platformTargets
  claude-code: CLAUDE.md           # present only if claude-code targeted
  # cursor: .cursor/rules/ · codex: AGENTS.md · generic: WORKSPACE_GUIDE.md

# ─── Present Clusters (what was generated) ───
clusters:
  adlc: true | false
  polc: true | false
  uxd: true | false
  polcTier2: true | false

# ─── Governance Home (GCE + TGE single canonical home — P3) ───
# DWG reserves these conventional paths; GCE/TGE populate the content
# and maintain .governance/GOVERNANCE_INDEX.md as the live inventory.
governance:
  home: .governance/
  index: .governance/GOVERNANCE_INDEX.md
  engine: .governance/engine/          # GCE + TGE core workflows
  rules: .governance/rules/            # GCE compliance rules
  agents: .governance/agents/          # all agent specs (GCE + TGE)
  hooks: .governance/hooks/            # canonical hook definitions
  test: .governance/test/              # TGE artifacts (was .tge/)
  driftRegister: .governance/drift-register.md
  complianceLog: .governance/compliance-log/
---
```

> **Governance home (P3):** ALL GCE + TGE content — engine, rules, agents, hooks, logs, test artifacts, state — lives under `.governance/`. DWG reserves the conventional paths in the manifest; GCE/TGE populate them and maintain `GOVERNANCE_INDEX.md`. Platform adapters (`.kiro/hooks/`, `.claude/agents/`, …) are thin pointers into `.governance/`. See layout design Part 3E principle P3.

## Generation Rules

### Rule 1: Only Include What Exists
Omit `paths`/`files` entries for clusters not generated. If ADLC absent → no `architecture:` path, no `technicalEnvironment:` file, no `src:`. Consumers checking a missing key treat it as "cluster not present, skip."

### Rule 2: Derive From the Actual File Set
Every entry reflects a file/folder DWG actually wrote in this generation. Never list aspirational paths.

### Rule 3: DWG is Sole Writer
Header says `DO NOT EDIT MANUALLY`. Only DWG writes the manifest (same custodianship as the baseline). Consumers read-only.

### Rule 4: Regenerate on Re-Baseline
On every generation and re-baseline, rewrite the manifest fresh (bump `baselineVersion`, refresh `generatedOn`, add/remove entries for added/retired files).

### Rule 5: `buildProfile` Parked
Do NOT populate `buildProfile` (build-method-agnostic). `storyStyle` and `platformTargets` ARE populated (active).

### Rule 6: Adapters Reflect Selected Platforms
The `adapters:` block lists ONLY the platforms selected at Config Gate Q2. Multi-target → multiple entries.

## Consumer Contract (How Downstream Reads It)

| Consumer | Reads | For |
|----------|-------|-----|
| **AI-GCE** | `paths.rules`, `files.*`, `clusters`, `platformTargets`, `storyStyle` | Discover rules to derive compliance; select enforcement mechanism per platform |
| **AI-TGE** | `paths.backlog`, `files.userStories`, `storyStyle` | Find stories/ACs to derive tests; know the AC format |
| **AI-FLO** | `files.driftRegister`, `paths.*` | Track position, route drift |
| **Future pkg** | any semantic key | Discover without coordination |

**Backward compatibility:** if a consumer finds NO manifest (legacy pre-manifest workspace), it falls back to a legacy hardcoded scan + warns "legacy workspace — no manifest found." (Implemented consumer-side in GCE P5.5 / TGE P5.6.)
