# GAEP for Rider

This host is a thin Rider tool-window client for the shared `gaep-engine` stdio protocol. It deliberately contains no duplicate Product, governance, adapter, or authorization logic.

The native Product tool window reads the exact Product binding, exposes Codex/Claude readiness, guarded-selection, versioned-handoff, managed read-only execution, Managed Run evidence, and exact staged-review flows, and provides bounded portable-design metadata list/read/import actions. Readiness conservatively projects verified adapter, runtime, model, and capability metadata. Selection can record one detected adapter, verified or engine-revalidated model ID, and non-sensitive portable settings after explicit confirmation. It fails closed for active Runs, capability drift, legacy or invalid state, and post-Run changes that require a versioned handoff. Handoff binds the exact current selection and latest terminal Run to a freshly observed changed target, requires bounded portable history plus cancel-default confirmation, rechecks state before submission, and atomically records the handoff and target selection. Selection and handoff do not start or resume a provider, create a Run, approve tools or effects, or grant execution authority. Executable paths, provider credentials, sensitive settings, and raw engine output are withheld.

Managed read-only execution renders and independently verifies an exact Charter/Workflow preview before a separate cancel-default attestation, fixes the timeout at 120 seconds, denies every Tool, write and non-observation effect, and renders the terminal provider disposition separately from the governed outcome. The Managed Run evidence actions are observation-only and audit-gated: the list shows a snapshot-bound first page of at most 100 records with exact total and omission counts, and exact read verifies one result/evidence projection by UUID and digest. Only portable IDs, states, counts, digests, warning codes and timestamps are displayed. Prompts, provider output, source bytes, changed paths, executable paths, process state, workspace paths and credentials are omitted. The view cannot start, resume, cancel, apply, discard, approve, or grant outcome, implementation-readiness, release, Tool, write, effect, or future Run authority. Interactive later-page navigation is not yet exposed.

Exact staged review is a separate mutation-capable workflow for one pending `codex-staged` Managed Run. Rider verifies one positive Run revision, canonical preview digest, result/evidence binding, complete sorted changed-file inventory of at most 512 entries with zero omissions, exact before/after digest-size-mode triples, excluded-path digest, and a host-owned write envelope of at most 256 scopes. Opening the review is read-only. Apply or discard requires a first cancel-default decision and a second cancel-default confirmation bound to the displayed Run ID, revision, preview digest, inventory digest, and—when applying—write envelope. The client sends no caller-selected paths. It rejects stale, rebound, private-path, extra-field, incomplete-metadata, non-canonical-digest, and invalid-transition responses. Apply records post-apply Workflow gates as `not-assessed`, so provider completion cannot be promoted to governed outcome satisfaction. Apply/discard receipts prove verified persisted state only; machine-local stage and recovery-journal cleanup remain separate claims.

Import selects one existing local folder, rechecks Product identity and revision before the request, retains only engine-validated metadata and digests, and always reports the result as pending human review. Files, archives, `.fig` ingestion, remote URLs, OAuth, live design-tool accounts, raw source content, local paths, credentials, and upstream approval escalation are outside this surface.

The development client resolves `gaep-engine` from `PATH` or `GAEP_ENGINE_EXECUTABLE` to a canonical absolute file, captures its SHA-256 on first launch, and revalidates the path and digest before every restart and immediately after process start. `GAEP_ENGINE_SHA256` may provide an expected 64-character digest (with an optional `sha256:` prefix). Requests are serialized and JSON-validated, stderr is drained, response frames are bounded, and process-tree termination is attempted on failure or disposal. Capturing a locally selected digest detects replacement but is not a publisher-authenticity claim.

Release packaging will bundle signed platform-specific engine binaries and supply their approved digests before launch.

Build requirements follow the official IntelliJ Platform Gradle Plugin 2.x baseline: Gradle 9 or newer and Java 17 or newer. The configured toolchain is Java 21.

From the repository root, `npm run test:rider:package` performs a clean test, mandatory IntelliJ bytecode instrumentation, plugin assembly, archive-structure verification, and exact byte/digest parity between the packaged JAR and the isolated Rider 2025.3 prepared sandbox without parallel instrumentation. It also revalidates the sandbox descriptor's exact ID, version, and GAEP tool-window factory. The installable output is `apps/rider/build/distributions/gaep-rider-0.1.0.zip`, with stable plugin ID `dev.gaep.productstudio`. This local package gate proves prepared-sandbox placement, not plugin-manager installation, native interactive `runIde` behavior, or Marketplace signing.

`npm run test:rider:startup` launches the resolved Rider 2025.3 runtime in a bounded process group, waits up to 90 seconds for fresh log evidence that exact plugin `dev.gaep.productstudio@0.1.0` loaded with the isolated GAEP config, system, plugin, and log paths, then terminates the sandbox process tree. It proves native runtime startup and plugin loading on the executing host. It does not automate the tool-window UI, prove packaged engine execution, test plugin-manager installation, interactively accept the staged-review confirmations, or grant host acceptance.
