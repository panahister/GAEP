# GAEP for Kiro

GAEP for Kiro is a local Code OSS/Open VSX-compatible extension boundary for the GAEP engine host. It exposes a static Product Studio panel, path-free Codex/Claude readiness and guarded-selection commands, managed read-only execution and evidence commands, an exact bounded staged-review command, phase-scoped, exact Change/Impact, exact Agent/Model, and accessible dashboard-table commands, and protocol-v2 import, list, and exact-read commands for portable-design snapshot metadata.

The readiness command is observation-only. The selection command can record one verified adapter, model, and set of non-sensitive portable settings after explicit confirmation. It fails closed for active Runs, capability drift, legacy or invalid selection state, and post-Run changes that require a versioned handoff. The handoff command binds the current selection and latest terminal Run to a freshly observed target, requires portable history details and a second cancel-default confirmation, then atomically records the versioned handoff and target selection. Selection and handoff do not start a provider, create or resume a Run, approve tools or effects, or grant execution authority. Executable paths, provider credentials, raw engine output, and sensitive settings are never rendered or stored in portable records.

The managed read-only command accepts the UUIDs of an already-confirmed exact Execution Charter and its bound Workflow Plan. It first renders a strict, path-free preview containing the exact identities, digests, workflow steps, and gate criteria. Execution requires a cancel-default human attestation to that preview digest. The engine rechecks the digest, denies every Tool, write scope, and non-observation effect, applies a 120-second timeout, and returns only a verified metadata-and-digest receipt. If staged changes appear, GAEP attempts to discard them and withholds a success receipt. Provider completion and governed outcome satisfaction remain separate fields and grant no approval or future authority.

This is a single bounded request over the local stdio host. Kiro cannot yet stream progress, interactively cancel, or resume this managed Run. It also does not create the Product, Initiative, managed Charter, Context Packs, Workflow Plan, or Tool Selection required by the flow; those exact governed records must already exist.

The Managed Run evidence command is read-only and audit-gated. It loads inventory pages with a fixed limit of 100, reports the exact total and omitted count, and exposes next/previous navigation under the first page's exact snapshot digest and total. A changed snapshot, total, offset, count, non-progressing page or private field fails closed. Selecting one Run loads an exact result/evidence projection only after server-side digest and identity verification. The projection contains portable IDs, states, counts, digests, warning codes and timestamps; it omits prompts, provider output, source bytes, changed paths, executable paths, process state, workspace paths and credentials. It cannot start, resume, cancel, apply, discard, approve, or grant any Run, Tool, write, effect, outcome, implementation-readiness, or release authority.

The phase-dashboard command binds an explicit Phase 0/1A projection to the exact current Product revision and digest, independently verifies the canonical three-panel catalog and composition digest, and shows the phase slice plus required Change/Impact and Agent/Model views. Phase-specific applicability remains unknown until a governed decision is bound. The command is read-only and cannot assert phase entry, approval, readiness, acceptance, or release authority.

The Change/Impact command obtains an audit-gated metadata-only catalog bound to the exact current Product, lets the user select one exact current Change, and then independently verifies the complete dashboard shape, Product/Change bindings, snapshot digest, bounded counts, portable locators, trace assessments, governance state, freshness, omissions, and no-authority boundary. It withholds Product, Change, and Work Item text, source bytes, absolute paths, provider material, and credentials. Approval is always shown as not established because the current contract has no general Change approval record.

The Agent/Model command re-probes the complete current capability set, reads the exact selected, unselected, migration-required, or invalid state, and binds those digests plus the current Product to one audit-gated dashboard request. The strict client independently verifies every capability, selection, Run, Managed evidence, handoff, reconciled count, freshness state, unavailable usage/cost metric, no-authority literal, and canonical snapshot digest before rendering metadata-only text. Extra or private fields, partial/rebound bindings, invented metrics, inconsistent freshness/counts, and post-digest mutation fail closed. The command cannot select or switch an agent, create a handoff, launch a Run, authorize a Tool/write/effect, approve an outcome, or establish provider-account or native-host readiness.

The separate accessible-tables command preserves the existing non-interactive dashboard commands and adds a native keyboard and screen-reader flow over the same strict Phase, Change/Impact, and Agent/Model responses. It lets the user select one table, keep verified source order or deterministically sort a visible column, and enter an optional case-insensitive filter of at most 256 characters over only the already-visible metadata cells. The resulting plaintext alternative states the exact visible, bounded, omitted, and source totals plus snapshot, source, and authority boundaries. A separate explicit action can copy CSV for only the currently visible columns and filtered rows to the clipboard; it writes no file, includes no omitted record or hidden field, and neutralizes spreadsheet-formula prefixes. These local presentation operations grant no state, approval, Run, Tool, write, effect, readiness, release, or acceptance authority.

The separate staged-review command accepts one exact pending Managed Run UUID and audit-verifies its current durable review. It renders the complete bounded inventory of at most 512 workspace-relative changed paths with kind, before/after digest, size and mode, plus the exact write envelope and revision-bound preview digest. Source bytes, provider output, absolute paths and machine-local authority remain withheld. Opening the review mutates nothing. Apply and discard each require an explicit choice followed by a second modal confirmation; dismissing either modal keeps the review pending. The client sends only the Run UUID, reviewed revision, preview digest, portable actor and exact decision literal. The engine regenerates and revalidates the review before acting, owns all stage/apply/discard operations, and returns an audit-verified persisted transition. Kiro receives no general filesystem-write API.

Restarted staged apply uses an explicit conservative host policy: post-apply Workflow gates are recorded `not-assessed`. The exact reviewed files may be applied, but this surface cannot claim governed outcome satisfaction; a resulting `failed`, `unknown`, or `conflict` state remains truthful. Discard persists governed discard evidence, while machine-local stage and recovery-journal cleanup remain separate unproven claims. Inventories above 512 files fail closed on this bounded cross-host surface and require a narrower staged Run or another exact engine review workflow.

The packaged extension defaults to its package-local `dist/gaep-engine.mjs` bundle and sends no requests to external services. The build computes that bundle's SHA-256 and embeds the exact digest into the separately built extension bundle. At every engine start, the client resolves both the compatible host runtime and packaged module to canonical regular files, verifies the packaged module against the embedded digest, binds both identities, starts the host runtime in its explicit Node mode, and rechecks both files immediately after process start. Provider and credential environment variables are not inherited. This detects package-local replacement; it is not publisher signing, provenance, notarization, or supported-platform certification.

An operator may instead set the machine-scoped `gaepKiro.engineExecutable` to a local external engine name or absolute path and optionally pin it with `gaepKiro.engineSha256`. Workspace-scoped overrides are rejected. An external digest without an external executable is also rejected so it cannot be mistaken for the embedded package pin. Import accepts one existing local folder. Files, archives, `.fig` ingestion, OAuth, network fetches, live design-tool accounts, and provider credentials are outside this extension.

Every imported snapshot remains `pending-human-review`. An upstream `approved` source-review value is preserved only as a claim; it is not GAEP approval, a Design Baseline, implementation readiness, or release readiness.

`npm run verify` typechecks, unit-tests, builds the package-local engine, packages `dist/gaep-kiro.vsix`, and independently verifies the exact seven-file bounded archive. The archive verifier rejects duplicate, directory, traversal, extra, missing, oversized, rebound, or byte-drifted entries; requires the exact `gaep.gaep-kiro@0.1.0` identity, workspace extension kind, Code OSS engine range, limited untrusted-workspace boundary, 14 unique command/activation bindings, and executable-code manifest markers; matches the packaged manifest, README, license, extension bundle, and engine bundle to their built sources; and verifies that the extension embeds the exact engine digest. `npm run test:extension-host` rebuilds and verifies that VSIX, installs a transparent synthetic `0.0.9` package-manager fixture, proves upgrade to exact `0.1.0`, same-version reinstall, forced fixture rollback, uninstall/absence and final `0.1.0` reinstall in an isolated compatible-host profile, then activates the exact installed package through a separate test harness. The harness hashes the installed engine bytes, verifies that exact digest is embedded in the installed extension bundle, executes the real empty audit-gated Managed Run evidence workflow through the package-local engine, verifies the bounded projection, and proves no `.gaep` workspace mutation. The lifecycle never touches a normal profile. The fixture is not a historic GAEP build, supported package, release artifact, or production rollback payload; the verifier and harness prove exact package structure, host-level version replacement, and one read-only packaged-engine workflow, not publisher signing, provenance, data/schema migration compatibility, or native Kiro acceptance. Native Kiro runtime behavior remains unverified when no Kiro binary is installed.
